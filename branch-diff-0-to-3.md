# Code Differences: `0-microsoft-template` → `3-configuration`

This document explains the code changes between the two branches. Branch `0-microsoft-template` is the default ASP.NET Web API project generated by the `dotnet new webapi` template. Branch `3-configuration` transforms it into a real application with structured configuration, a separate class library, and Swagger UI.

---

## 1. New `Configuration` Class Library

The most significant change is the addition of a new **`Configuration` project** — a separate class library referenced by `AppWebApi`.

### `Configuration/Configuration.csproj`
- Targets `net10.0` with nullable disabled.
- Declares a `UserSecretsId` so that **ASP.NET User Secrets** are stored in this assembly (not in `AppWebApi`). This is intentional: the same assembly is used both at runtime and at design time (e.g. EF Core migrations), so secrets need to be attached here.
- Embeds **build-time metadata** into the assembly via `<AssemblyMetadata>` items: `BuildTime`, `BuildMachine`, `BuildUser`, and `CompanyUrl`. These are stamped at compile time using MSBuild property functions.
- Includes NuGet packages for configuration (`Microsoft.Extensions.Configuration.*`), options (`Microsoft.Extensions.Options`), logging, JWT/crypto, and **Azure Key Vault** (`Azure.Security.KeyVault.Secrets`, `Azure.Extensions.AspNetCore.Configuration.Secrets`) — preparing for a later branch that will switch between User Secrets (dev) and Key Vault (production).

### `Configuration/Options/` — The Options Pattern

Each class in this folder represents a strongly-typed section of `appsettings.json` or User Secrets, following the [ASP.NET Options Pattern](https://learn.microsoft.com/en-us/aspnet/core/fundamentals/configuration/options).

| File | `Position` (config section key) | Purpose |
|---|---|---|
| `AesEncryptionOptions.cs` | `"AesEncryption"` | AES key, IV, salt, and iteration count for symmetric encryption. Has a `HashKeyIv` method that accepts a delegate to derive byte arrays from the raw string values. |
| `DbConnectionDetailOptions.cs` | *(child of `DbConnectionSetsOptions`)* | A single database connection entry: login, connection name, and connection string. |
| `DbConnectionSetsOptions.cs` | `"ConnectionSets"` | A hierarchy of database connection sets (`DataSets` and `IdentitySets`), each containing a list of `DbSetDetailOptions` (which in turn hold `DbConnectionDetailOptions` entries). Supports multiple databases with different user roles. |
| `JwtOptions.cs` | `"JwtConfig"` | All JWT bearer token settings: signing key, issuer, audience, lifetime, and validation flags. |
| `MySecretOptions.cs` | `"MySecret"` | A simple demo options class (a `Message` string and a `Number`) backed by a User Secret — used to demonstrate that secrets injection works. |
| `VersionOptions.cs` | *(populated from assembly, not config file)* | Reads version, build, and company metadata from the `Configuration` assembly at runtime using reflection (`Assembly.GetCustomAttribute<...>`). Also extracts the short git commit hash from the `InformationalVersion` string using a regex (`\+([a-fA-F0-9]+)`). |

## 2. `AppWebApi` — Project File Changes (`AppWebApi.csproj`)

- **Nullable disabled** (`<Nullable>disable</Nullable>`), consistent with the `Configuration` project.
- **Swagger replaces OpenAPI minimal**: `Microsoft.OpenApi` is removed; `Swashbuckle.AspNetCore` is added.
- **`Microsoft.AspNetCore.Mvc.NewtonsoftJson`** is added to handle JSON serialization (reference loop handling).
- A **`<ProjectReference>`** to `Configuration/Configuration.csproj` is added.
- Two empty `<PropertyGroup Condition>` entries for `http`/`https` run configurations are added (VS Code launch profile stubs).

---

## 3. `AppWebApi/Program.cs` — Bootstrap Overhaul

The `Program.cs` grows from ~20 lines to ~87 lines. The key additions:

### CORS
A **permissive global CORS policy** is registered (`AllowAnyOrigin`, `AllowAnyHeader`, `AllowAnyMethod`). This is intentional for a training API consumed by JS/React frontends.

### JSON Serialization
Controllers are configured with `NewtonsoftJson` and `ReferenceLoopHandling.Ignore`, preventing stack overflows when serializing object graphs with circular references (important once EF Core entities are introduced in later branches).

### Configuration Bootstrap (User Secrets via reflection)
```csharp
var assembly = System.Reflection.Assembly.Load("Configuration");
builder.Configuration
    .SetBasePath(Path.Combine(currentDir, "../AppWebApi"))
    .AddJsonFile("appsettings.json", optional: true, reloadOnChange: true)
    .AddUserSecrets(assembly);
```
User Secrets are loaded using the **`Configuration` assembly** (not the entry assembly). The comment explains the reason: EF Core migrations run at design time and need to find secrets through the same assembly, so it must be `Configuration`, not `AppWebApi`.

### Options Registration
All five option classes are registered with `builder.Services.Configure<T>(...)`:
- `AesEncryptionOptions`, `JwtOptions`, `DbConnectionSetsOptions`, `MySecretOptions` — each bound from the matching `appsettings.json` section via `GetSection(...).Bind(options)`.
- `VersionOptions` — populated via the static `VersionOptions.ReadFromAssembly(options)` method instead of from config.

### Swagger (replaces minimal OpenAPI)
`AddSwaggerGen` is configured with a `SwaggerDoc` that injects live values from `appsettings.json` into the description (dataset tag, default user). Swagger UI is enabled unconditionally (not just in Development) for training convenience:
```csharp
// if (app.Environment.IsDevelopment())   <-- commented out
{
    app.UseSwagger();
    app.UseSwaggerUI(...);
}
```

## 4. `AppWebApi/Controllers/` — Controller Swap

### `WeatherForecastController.cs` — **Deleted**
The default template controller that returned random weather data is removed entirely.

### `AdminController.cs` — **Added**
A new `AdminController` with the route `api/admin/[action]` exposes two endpoints:

| Endpoint | Method | Returns |
|---|---|---|
| `GET api/admin/Version` | `IActionResult` | The `VersionOptions` object (assembly/build info) |
| `GET api/admin/MySecret` | `IActionResult` | The `MySecretOptions` object (from User Secrets) |

The constructor uses **constructor injection** to receive all five options classes via `IOptions<T>`, unwrapping each with `.Value`. This demonstrates how the Options Pattern makes configuration available throughout the application.

---

## 5. `AppWebApi/appsettings.json` — Expanded

The minimal two-key file is replaced with a richer structure:

- **Logging**: Expanded to configure separate log levels per provider (`Console`, `InMemory`) and per namespace (`AppWebApi.Controllers`, `DbRepos`, `Services`). This allows fine-grained control — e.g. suppressing controller logs on the console while keeping them in the in-memory provider.
- **`ApplicationSecrets`**: A new section with `SecretStorage: "UserSecrets"` indicating which secret backend to use (to be switched to `"AzureKeyVault"` in a production branch).
- **`DatabaseConnections`**: A new section declaring the active dataset tag (`sql-music.sqlserver.docker`), default data user, and migration user. Inline comments list the other valid values.

## Summary

| Concern | `0-microsoft-template` | `3-configuration` |
|---|---|---|
| API documentation | ASP.NET minimal OpenAPI (`MapOpenApi`) | Swashbuckle Swagger UI |
| Configuration | Only `appsettings.json` basics | Options Pattern with strongly-typed classes |
| Secrets | None | ASP.NET User Secrets via `Configuration` assembly |
| JSON serializer | `System.Text.Json` (default) | Newtonsoft.Json with loop handling |
| CORS | None | Permissive global policy |
| Controller | `WeatherForecastController` (demo) | `AdminController` (version + secret endpoints) |
| Project structure | Single project | Two projects: `AppWebApi` + `Configuration` library |
